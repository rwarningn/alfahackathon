# Дело в движении — умный кредитный кабинет

Локальный прототип для Альфа Хак: малый бизнес подаёт заявку на оборотные средства, аналитик видит очередь, получает объяснимую рекомендацию и принимает решение. Клиент видит статус, историю и меняющуюся ленту следующих шагов.

**Только синтетические данные. Это учебный прототип, не банковский сервис.**

## Запуск

Рекомендуемый воспроизводимый запуск: Docker Engine / Docker Desktop с Compose v2.

```sh
docker compose up --build -d
```

Откройте http://localhost:8000. Остановка: `docker compose down`. Данные остаются в named volume `credit-data`; не удаляйте volume, если хотите их сохранить.

Без Docker: Python 3.12.7, внешние Python-пакеты не требуются.

```sh
python app.py
```

Python зафиксирован в `.python-version` и Dockerfile. На машине разработки также можно проверить совместимость с другим Python 3.12+. Стандартная библиотека поставляется вместе с Python; requirements.txt не содержит внешних зависимостей.

## Демо-аккаунты

| Логин | Пароль | Роль |
|---|---|---|
| client | client-demo | Клиент Руслан |
| bank | bank-demo | Аналитик Егор |
| other | other-demo | Второй клиент для проверки изоляции |

Выбор роли на экране заполняет соответствующий демо-пароль. Создание заявок доступно только клиенту; изменение статусов — аналитику. Клиент получает только собственные заявки.

## Проверка основного сценария

1. Войдите как клиент, подайте заявку с предзаполненными показателями. Запишите номер.
2. Проверьте начальный статус, расчёт платежа и причину рекомендации. Обновите страницу: заявка сохранена.
3. Выйдите и войдите как банк. Добавьте комментарий и нажмите «Взять в работу».
4. Добавьте объяснение и одобрите либо отклоните заявку. Финальное решение изменить нельзя.
5. Войдите как клиент: проверьте результат, три записи истории и новое содержимое ленты.
6. Войдите как `other`: чужая заявка не отображается.
7. Повторите с примерами из `data_examples.json`: возраст 9 месяцев даёт рекомендацию ручной проверки; расходы 1 150 000 ₽ — рекомендацию отказа.
8. Перезапустите приложение: заявки и история останутся, вход нужно повторить.

```sh
python -m unittest discover -s tests -v
```

## Архитектура и данные

Один сервис: браузер HTML/CSS/JS → HTTP JSON API Python → SQLite (WAL). Для команды из трёх человек это позволяет закончить связный сценарий без распределённых транзакций. Правила оценки вынесены в `scoring.py`, чтобы Руслан мог менять их независимо от UI. Расчёт сохраняется вместе с версией политики и не меняется задним числом.

Подробности: [план команды](docs/TEAM_PLAN.md), [архитектура, состояния и модель данных](docs/ARCHITECTURE.md), [контракт OpenAPI](docs/openapi.json), [коллекция запросов](docs/requests.http), [проверка требований](docs/REQUIREMENTS.md).

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| HOST | 127.0.0.1 | Адрес сервера; в контейнере 0.0.0.0 |
| PORT | 8000 | Порт HTTP |
| DB_PATH | data/credit.db | Файл SQLite, нужен доступ на запись |

Docker публикует порт только на loopback хоста. Пароли намеренно публичные и предназначены для локальной демонстрации. Сессии случайные, в памяти, срок 8 часов; cookie HttpOnly / SameSite=Strict. HTML экранирует пользовательский текст; SQL использует параметры. Переход и запись истории выполняются одной транзакцией, конфликт возвращает 409. Денежные расчёты здесь приближённые (float), в банковской реализации нужен Decimal / целые копейки.

## Границы и развитие

Реализованы: один продукт, два типа ролей, подача, оценка, ручное решение, история и лента по статусу. Рекомендация не подменяет решение аналитика. Ставка 24% — синтетическая константа, не тариф Альфа-Банка. Правила не обучены и не прошли банковскую валидацию. Документы, KYC/ФНС/БКИ, подписание и перечисление денег не реализованы. Лента — локальные сообщения по состоянию заявки, без внешних новостей. Это явное упрощение требования о персональной новостной ленте, которое стоит уточнить у организаторов.

До публичного размещения нужны полноценная авторизация (OIDC), удаление демо-паролей, TLS и Secure-cookie, лимиты попыток входа, устойчивое хранилище сессий, журнал администрирования, резервное копирование и production HTTP server. Встроенный HTTP-сервер, SQLite и память одного процесса рассчитаны на локальный показ, а не банковскую нагрузку. Контейнер запускается без root, состояние вынесено в volume; это старт упаковки, а не подтверждение полной enterprise-готовности.

LLM отсутствует: основной сценарий не зависит от сети, платных API или моделей. Дальнейший ИИ имеет смысл для объяснения недостающих данных или извлечения показателей из документов; при использовании LLM требования допускают только открытые веса.
